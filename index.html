Phase 2 · AI 영향도 분석 및 코드 자동화
8 – 10
⬜
8
영향도 분석 실행 (Type 1 / Type 2 분기)
🔵 Type 1 — 독립 커스텀
  • ① 표준 AS-IS / TO-BE 버전 코드 로컬 캐시 확보
  • ② 표준 AS-IS → TO-BE 변경 diff 생성
  • ③ 커스텀 AS-IS 코드 캐시 확보
  • ④ 표준 AS-IS와 커스텀 AS-IS를 비교해 커스텀 수정 패치(delta) 추출
  • ⑤ 관련 코드 블록만 선별 (200KB 상한 적용)
  • ⑥ Claude 분석 → 이식 시 충돌 지점 + 수정 계획
🟣 Type 2 — 표준+커스텀 연동
  • ① 커스텀 프로젝트 전체 커밋 이력을 패치 형태로 추출
  • ② TO-BE 표준 코드 캐시 확보
  • ③ Claude 분석 → 커밋 이력 + TO-BE 표준 기준으로 재적용 충돌 지점 + 가이드 도출
  • ⚠️ 항상 수동 재적용 필요
📋 공통 출력 결과
  • 🎯 위험도 판정: 낮음 / 중간 / 높음 + 충돌 지점 목록 + 수정 계획
  • 💬 Redmine 댓글 초안 자동 생성
  • ⚠️ JDK 21 마이그레이션 주의사항 자동 추가 (대상 버전 이상인 경우)
  • ❌ 커스텀 코드 미확보 등 치명적 오류 → "판단 불가" 처리
